# x-article-publish

把一篇文章自动填进 X 长文（Articles）编辑器：标题、正文格式、图片、封面。工具填完就停下，你自己检查预览后手动点发布。**工具绝不自动发布。**

可以当 Claude Code 插件用（对 Claude 说一句“把这篇文章发到 X”就行），也可以当命令行工具 `x-article-fill` 单独用。

需要：Node.js 18 或更高版本、本机安装的 Google Chrome、一个能写长文（Articles）的 X 账号。

## 方式一：作为 Claude Code 插件安装（推荐）

在 Claude Code 里运行：

```
/plugin marketplace add guanqinghu520-gif/x-article-publish
/plugin install x-article-publish@x-article-publish
```

之后对 Claude 说“把 ~/文章/我的文章.md 发到 X”，它会预检文章、选好标题和封面、在后台完成填写，最后告诉你要检查什么。第一次使用时它会引导你登录 X。

## 方式二：作为命令行工具安装

```bash
git clone https://github.com/guanqinghu520-gif/x-article-publish.git
cd x-article-publish
npm install
npm link        # 之后在任何目录都能直接用 x-article-fill 命令
```

## 使用

**第一次使用先登录（只需一次）：**

```bash
x-article-fill --login
```

这会打开一个普通的 Chrome 窗口（不受工具控制）。在里面登录 X，用 Google 登录也可以。看到 X 首页后，按 Cmd+Q 退出这个 Chrome，登录状态就保存在 `~/.x-article-fill/chrome-profile` 里了。工具不保存、也不处理你的账号密码。

> 为什么要单独登录：Google 不允许在被自动化工具控制的浏览器里登录（会提示「This browser or app may not be secure」），所以登录要在普通窗口里完成。

**之后每次发文：**

```bash
x-article-fill ~/文章/我的文章.md
```

运行过程：

1. 打开一个 Chrome 窗口，进入 X 长文页面并新建草稿。如果发现还没登录，会停下来提示你。
2. 文章所在文件夹里如果有 `cover` 开头的图片（如 `cover.jpg`），会设为封面；也可以用 `--cover` 指定。
3. 依次填写标题、正文和图片，每张图上传完再处理下一张。
4. 终端显示「已填写完成，请检查后手动发布」。浏览器保持打开，你检查预览后自己点发布。关闭浏览器窗口，工具就结束。

先看看文章会被解析成什么样（不打开浏览器）：

```bash
x-article-fill 我的文章.md --dry-run
```

### 文章写法

| Markdown | 在 X 长文里 |
| --- | --- |
| 第一个 `# 标题` | 长文标题（不进正文） |
| `## 小标题` | Heading |
| `### 小标题`（及更小） | Subheading |
| `**加粗**` `*斜体*` `~~删除线~~` | 对应格式 |
| `- 列表` / `1. 列表` | 无序 / 有序列表 |
| `> 引用` | 引用 |
| `[文字](链接)` | 链接 |
| `![说明](images/图1.png)` | 在这个位置上传图片 |
| 代码块、表格 | X 不支持，分别转成引用、每行一段文字，终端会提示 |
| `---` 分隔线 | 忽略，终端会提示（需要的话在编辑器里手动插入 Divider） |

- 图片路径相对于文章所在文件夹，绝对路径和 `~/` 也可以。
- 图片要单独放一行（前后空一行）。写在段落中间的会被拆成单独一行。写在列表或引用里的会报错，因为 X 不能在那里放图。
- 也支持 `.html`、`.htm`、`.docx`（Word）、`.txt`。Word 里的图片会自动提取出来上传。

### 选项

| 选项 | 作用 |
| --- | --- |
| `--login` | 打开普通 Chrome 窗口登录 X（第一次使用，或登录过期时） |
| `--dry-run` | 只解析文章、打印结果，不打开浏览器 |
| `--title <标题>` | 指定长文标题（默认用文章里第一个 `# 标题`） |
| `--cover <图片>` | 指定封面图片（X 长文封面比例约 5:2） |
| `--no-cover` | 不设置封面 |
| `--profile <目录>` | 换一个浏览器配置目录（比如另一个登录状态） |
| `--config <文件>` | 用自己的选择器配置覆盖默认值（见下文） |
| `--paste event` | 正文改用页面内粘贴事件写入（默认 `clipboard`：真实的 Cmd+V 粘贴，会覆盖你当前剪贴板里的内容） |

## 出错时

提示「浏览器配置目录正被占用」，说明上一次打开的 Chrome 还没退出。找到那个窗口，按 Cmd+Q 退出后重试。

任何一步失败（找不到图片、上传超时、页面上找不到某个按钮），终端会写明是哪一步、第几张图出错，并在 `~/.x-article-fill/logs/` 保存一张截图。浏览器会保持打开，方便你查看现场。所有图片路径在打开浏览器之前就会检查，缺图会直接列出来。

## X 改版了怎么办

页面元素的定位都写在 [src/selectors.json](src/selectors.json) 里，中英文界面的按钮名都已列出。比如 X 把「Insert」按钮改名了，只要改 `imageMenuSteps` 里对应的名字。也可以把要改的项写进一个单独的文件，用 `--config 我的配置.json` 传入，这样不会改动原文件。

每一项是候选列表，按顺序尝试：

- `{"role":"button","name":"/^(Insert|插入)$/i"}`：按钮名（可以写正则）
- `{"css":"..."}`：CSS 选择器
- `{"placeholder":"Add a title"}`：输入框的占位文字
- `"within":"[role='dialog']"`：只在弹窗里找

`timing` 控制操作之间的随机停顿和超时时间。

**安全拦截**：所有点击都会先检查按钮文字。名字是 Publish、发布、Post、Schedule 这类的按钮（见 `forbiddenClickNames`），工具会直接拒绝点击并停止。

## 工作原理

1. 把文章转成 HTML。每张图片的位置先放一行占位文字（如 `XAFIMG001XAF`）。
2. 把整段 HTML 粘贴进编辑器，由 X 编辑器自己的粘贴规则转成小标题、加粗、列表等格式，所以不会出现 Markdown 符号。
3. 依次找到每个占位行，删掉文字，在这个空行上通过「Insert → Media」上传图片。文件直接交给网页的上传控件，不弹系统选择窗口。等这张图上传完，再处理下一张。
4. 最后检查：占位行都已替换，图片数量对得上，正文里没有残留的 Markdown 符号。

## 测试

```bash
npm test                 # 用本地模拟的编辑器（基于真实的 Draft.js 编辑器框架，X 的发帖编辑器用的也是它）跑完整流程
npm test -- --headed     # 显示浏览器窗口
```

测试文章在 `test/sample/article.md`：3 张图，包含小标题、加粗、斜体、列表、引用和链接。它会检查格式和图片位置与原文一致、没有点击发布，并单独测试安全拦截。

## 使用约束

- 只用于自己的账号，低频使用。
- 发布永远由你手动完成。
