# 发布文章到 X 长文

用插件自带的 `x-article-fill` 命令行工具完成填写。插件根目录是 `${CLAUDE_PLUGIN_ROOT}`（说明见那里的 README.md）。

下文的 `x-article-fill` 都指：本机已有 `x-article-fill` 命令就直接用；没有就用 `node "${CLAUDE_PLUGIN_ROOT}/bin/x-article-fill.js"`。

**铁律：绝不点击发布。** 发布永远由用户本人完成。不要用任何浏览器工具去操作 X 页面，不要输入账号密码。

## 步骤

### 1. 确认文章和工具

- 用户给的是文件就直接用；给的是文件夹，就找其中的 `.md`（其次 `.docx` / `.html`）。有多篇时问用户是哪一篇。
- 确认工具可用：`command -v x-article-fill`，或者 `${CLAUDE_PLUGIN_ROOT}/node_modules` 存在。都没有的话，在 `${CLAUDE_PLUGIN_ROOT}` 里运行 `npm install --omit=dev`。需要 Node.js 18+ 和本机安装的 Google Chrome。

### 2. 决定标题和封面

- **标题**：文章同目录下如果有 `发布信息.txt`（或类似的发布说明），读出其中【标题】一节作为标题，用 `--title "..."` 传入；否则用文章里第一个 `# 标题`（不传 `--title`）。和文章里的标题不同时，在回复里说一句用了哪个。
- **封面**：工具会自动选同目录下 `cover` 或 `封面` 开头、最宽的那张图。用户另外指定了封面，或发布说明里写了封面文件，就用 `--cover "<完整路径>"`。X 长文封面比例约 5:2。

### 3. 预检

```bash
x-article-fill "<文章完整路径>" [--title "..."] [--cover "..."] --dry-run
```

- 报“找不到图片”等错误：把缺的文件列给用户，停下，不要继续。
- 有 ⚠ 提示（代码块、表格、分隔线等被转换或忽略）：在最后的回复里一并告诉用户。
- 不用把整段 HTML 贴给用户，只说标题、封面、图片张数和提示。

### 4. 填写（后台运行）

预检通过后直接开始，不必再征求同意：

```bash
x-article-fill "<文章完整路径>" [--title "..."] [--cover "..."] --close-previous
```

- 用 Bash 的 `run_in_background: true` 运行。工具填完后会一直开着浏览器等用户检查，进程不会自己结束。
- `--close-previous` 会自动关掉上一次运行留下的浏览器（未发布的内容 X 已自动存为草稿）。
- 开始时告诉用户：会弹出一个 Chrome 窗口，填写期间（几分钟，图片多会久一些）不要点那个窗口。
- 等待输出里出现 `已填写完成` 或 `出错步骤`：另起一个后台命令，用循环 grep 等这两个词之一出现（上限 15 分钟），它结束时你会收到通知。不要反复短间隔轮询。

### 5. 处理结果

**成功**（出现 `已填写完成`）：告诉用户可以检查了，给出检查清单：
- 封面是否需要在 X 的裁剪框里调整
- 小标题、加粗、列表、引用（多行引用应逐行显示）是否正常，没有 `**`、`#` 这类符号
- 每张图是否在原文对应的位置
- 点 Preview（预览）通读一遍，确认无误后**自己点发布**
- 发布完按 Cmd+Q 关掉那个 Chrome（不关也行，下次运行会自动关）

**未登录**（原因里有 `[未登录]`）：
1. 后台运行 `x-article-fill --login`（`run_in_background: true`）。
2. 告诉用户：在弹出的普通 Chrome 窗口里登录 X（可以用 Google 登录），看到首页后按 Cmd+Q 退出。
3. 等这个命令结束（后台任务结束时会通知你），输出里有“登录状态已保存”后，重新执行第 4 步。

**其他出错**：把“出错步骤”和“原因”告诉用户；用 Read 查看输出里给出的截图路径，判断原因：
- 页面上找不到某个按钮（多半是 X 改版或界面语言不同）：根据截图在 `${CLAUDE_PLUGIN_ROOT}/src/selectors.json` 里补上新的按钮名，再重试一次。改之前先告诉用户要改什么。
- 图片上传超时：可能是网络慢，重试一次；还不行就告诉用户。
- 不要静默跳过任何一张图，也不要自己去点页面。
